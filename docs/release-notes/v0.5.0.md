# mcp-clickhousex v0.5.0

**Released:** 2026-04-02  
**Previous release:** v0.4.0

This release adds first-class `SHOW` introspection alongside read-only `SELECT`, tightens MCP metadata so tools and resources stay aligned for agents, renames public Pydantic types for clarity, and hardens the test suite against local config interference.

---

## Highlights

### New MCP tool: `run_show`

Agents and operators often need ClickHouse’s native `SHOW` commands (`SHOW DATABASES`, `SHOW TABLES`, `SHOW CREATE TABLE`, settings, grants, etc.). Until now, only `run_query` (strictly `SELECT` / `WITH … SELECT`) covered ad-hoc SQL.

**`run_show`** runs a **single** `SHOW` statement per call and returns the same **`QueryResult`** shape as `run_query` (`columns`, `rows`, optional `truncated` / `row_limit`).

| Aspect | Behavior |
|--------|----------|
| **Allowed** | One statement, must start with `SHOW` (case-insensitive after leading whitespace). |
| **Rejected** | Empty SQL, multiple statements (`;` in the body), non-`SHOW` SQL (e.g. `SELECT`), and **`INTO OUTFILE`** (server-side export). |
| **Limits** | Same **`max_result_rows` + 1** / **`result_overflow_mode: break`** pattern as `run_query`, so overflow is detectable and results respect the profile row cap. |
| **Timeout** | Same **`max_execution_time`** (command timeout) as `run_query` for the profile. |
| **Session** | Optional **`database`**, **`profile`**, and **`parameters`** (driver placeholders `%(name)s` or `{name:Type}`) match `run_query` ergonomics. |

`run_query` is unchanged in intent: **read-only `SELECT` / `WITH … SELECT` only**, with the existing `validate_read_only` rules.

## MCP metadata and documentation

Tool docstrings, **`Field`** descriptions, and **resource** names/descriptions were brought in line with each other so clients see consistent, copy-paste-friendly guidance:

- Descriptions use the **`[ClickHouse] …`** prefix on the wire where appropriate; the README tables mirror the same wording **without** the prefix for human readers.
- Parameters that refer to other entities use **tag-based lineage** (e.g. **Src: profiles**, **Src: databases**, **Src: tables**) so agents know which list/discovery tool or resource to use first.
- **Resource URIs** and blurbs match the corresponding tools (`list_*`, `get_cluster_properties`, etc.).

End-to-end tests now **inspect tool descriptions and schema metadata** against the Python docstrings/fields, which reduces drift between code and MCP surface over time.

---

## Naming: `mcp-clickhousex` everywhere

The **FastMCP** server id, CLI/help text, README (including CI badge/links), and config path references now consistently use **`mcp-clickhousex`**, matching the PyPI package and filesystem config layout (`~/.config/mcp-clickhousex` on Unix). This avoids split-brain between docs, logs, and MCP client configs.

---

## Breaking changes (Python API)

If you import Pydantic models from **`mcp_clickhousex.models`**, types were renamed to drop redundant `*Model` suffixes (module scope already disambiguates them):

| v0.4.0 (old) | v0.5.0 (new) |
|--------------|--------------|
| `MCPModel` (base) | `MCPBase` |
| `ProfileModel` | `Profile` |
| `OptionDescriptorModel` | `OptionDescriptor` |
| `QueryLimitsModel` | `QueryLimits` |
| `ExecutionLimitsModel` | `ExecutionLimits` |
| `ClusterPropertiesModel` | `ClusterProperties` |
| `TabularResultModel` | `TabularResult` |
| `QueryResultModel` | `QueryResult` |
| `ExplainResultModel` | `ExplainResult` |

Composed types follow the same rename (e.g. `ExecutionLimitsModel.query` was `QueryLimitsModel`; it is now `ExecutionLimits.query` as `QueryLimits`). The shared base type was renamed from **`MCPModel`** to **`MCPBase`** to avoid confusion with **`pydantic.BaseModel`**.

MCP JSON shapes for tools/resources are unchanged aside from whatever your client already reflected from these types.

**Upgrade:** replace imports and type hints with the new names; a quick ripgrep for `Model` in your code against `mcp_clickhousex` imports is enough for most callers.

## Quality and testing

- **`conftest.py`** adds an autouse fixture that redirects **`_user_config_path`** so tests do not accidentally load a real **`~/.config/mcp-clickhousex`** tree during CI or local runs.
- New **unit tests** cover `validate_show_statement` and **`run_show`** success/error paths; **e2e** covers schema and basic `run_show` / rejection cases.

---

## Documentation (README)

- Clarified that **flat environment variables** are the straightforward way to configure the **default profile**, not only a legacy path.
- Minor spacing/formatting cleanup in the README.

---

## Migration checklist (from v0.4.0)

1. **MCP clients:** If you generate prompts from tool lists, mention **`run_show`** for introspection; keep **`run_query`** for analytics SQL only.
2. **Python embedders:** Update **`mcp_clickhousex.models`** imports per the table above.
3. **Operators:** No config file format change required; naming alignment is documentation and identity only.
